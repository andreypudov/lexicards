* Requirements

- macOS *13.5* or later
- Xcode *26* or later
- Swift *6.0*

Formatting uses =swift-format=, which ships with the Xcode toolchain, so there
is nothing to install.

The project is an AppKit and SwiftUI menu bar application. It is configured as
a UI-element application, so it does not appear in the Dock or present a normal
application window.

* Architecture

See [[file:docs/architecture.org][docs/architecture.org]] for the components, key flows, source layout, and design decisions.

* Build

Open =LexiCards.xcodeproj= in Xcode and run the shared *LexiCards* scheme.
The command-line equivalents go through the Makefile, which is also what CI
runs, so a green local run and a green pipeline mean the same thing:

#+begin_src sh
make build   # build the Release configuration into build/Release
make install # build and install to /Applications
make release # build and package dist/LexiCards-<version>.zip
make clean   # remove build/ and dist/
#+end_src

Pass =SIGN_IDENTITY="LexiCards Release"= to =make build= or =make release= to sign
with the release certificate. Without it, Xcode signs the build for local use.
The release workflow imports that certificate from the =SIGNING_CERT_P12= and
=SIGNING_CERT_PASSWORD= secrets, and fails if the built app is not signed by it.

=make build= produces =build/Release/LexiCards.app=. The zip that =make release=
writes is named for =CFBundleShortVersionString= in the built bundle, because the
Homebrew cask derives its download URL from the version.

* Formatting

The repository uses Apple's =swift-format=, configured in =.swift-format=.
It ships with the Xcode toolchain, so there is no dependency to install and no
version to drift against CI. From the repository root:

#+begin_src sh
make format # apply the rules in place
make lint   # report violations, failing on any finding
#+end_src

Run =make lint= before opening a pull request. Formatting changes should stay
separate from behavioral changes when practical.

* Testing

The project uses the Swift Testing framework. The shared Xcode scheme includes
the =LexiCardsTests= unit-test target. Run the suite from Xcode or with:

#+begin_src sh
make test
#+end_src

The current tests cover CSV loading, malformed and unreadable files, random
selection (including that a rotation never repeats the entry already on screen,
and that every entry is reachable), reloading over an existing vocabulary, and
empty-state behavior. They exercise the same API the app calls, so a passing
suite says something about the shipped behaviour.

Tests must not depend on =AppSettings=; it wraps =UserDefaults=, which is shared
mutable process state. Keep new logic testable without it.

The smoke test should verify that the app starts without a Dock icon, opens a
UTF-8 CSV file, rotates entries, toggles the card, speaks an entry when enabled,
restores the selected file after relaunch, and remembers the card position.

* Adding tests

Prioritize the platform-independent vocabulary behavior: CSV loading, empty and
malformed rows, and selection. Keep AppKit panel and menu tests focused on the
smallest integration behavior that cannot be covered at the service level.

* Pull requests

Before submitting a change:

1. Run =make lint=
2. Run =make test=
3. Run =make build= (see Pre-push verification below)
4. Exercise the affected menu or card workflow manually
5. Update [[file:docs/usage.org][docs/usage.org]] when user-visible behavior or file format changes, and [[file:docs/architecture.org][docs/architecture.org]] when the structure changes

** Pre-push verification

To catch compiler errors and optimizer crashes before they reach CI, run the
full gate locally. The three commands below are exactly what =.github/workflows/ci.yml=
runs, in the same order, so passing locally means passing in CI.

=make build= builds the *Release* configuration, which matters: Release-only
optimizer crashes have reached this project before and do not reproduce in a
Debug build.

#+begin_src sh
make lint
make test
make build
#+end_src

All three must pass before pushing. See [[file:AGENT.md][AGENT.md]] for notes on specific
optimizer issues.
